# Constructa: layered planes, a clearer rhythm

这轮设计的目标不是再叠加一批动画，而是让入口、导航、章节和项目介绍使用同一种视觉语言：
**色板组成空间，字体建立秩序，动效解释关系。**

## 设计判断

主题已经有可保留的辨识度：巨幅交错字体、斜向色面、像素地球、开放式编辑版面，
以及能阅读、链接和打印的真实文档。改进应围绕这些特点展开，而不是改成通用圆角卡片站。
新的共享标记由圆轨道、切开的几何主体、斜向梁和偏转方块组成；它作为原创身份线索，
串联加载、首页、导航和结尾，不用像素地球承担整个品牌的中心角色。

| 可以改进的地方 | 本轮方向 | 判断依据 |
| --- | --- | --- |
| 导航像一整条传统工具栏 | 品牌、章节、配色、索引分别成为独立色板 | 与构成主义的分体几何一致，也让功能层次更清楚 |
| 首次进入缺少统一的视觉过场 | 多色板依次弹出、交叠、汇合成全屏色面，再揭开真实页面 | 将等待转为短暂的品牌表达，不另造一套装饰语言 |
| 首页与作品展示需要更强的整体构图 | 巨幅字体与共享标记主导首页；项目使用整幅标题与主媒体 | 不让装饰压过名字与作品，也不把作品降为通用小卡片 |
| 多个元素同时动，容易争抢注意力 | 每个视口保留一个主动作，其余反馈轻量且快速 | 读者应先看见名字和作品，而不是研究所有效果 |
| 表现型标题与阅读信息的层级需要区分 | 展示字体负责性格，正文负责清晰，等宽小字负责注释 | 大字可以大胆，长段文字和按钮不能牺牲可读性 |
| 单张浅色截图不能表达完整主题 | 同屏展示 Signal 浅色与 Cobalt 深色，再给出完整功能图版 | 色彩系统与实用功能都需要直接证据 |
| 样式集中、较大组件承担过多职责 | 按基础层、组件、章节和滚动体验组织样式；提取重复结构 | 定制文案继续只编辑 `cv.json`，代码复用不能制造第二份内容源 |

本轮之前的导航参考是 [v1.0.0 的桌面预览](https://github.com/MiraHikari/astro-constructivist/releases/download/v1.0.0/desktop.png)。
新的宣传图应从改造完成的真实页面重新拍摄，不用概念图代替运行中的产品。

## 三个可继续发展的灵感方向

### 1. 色面装配：让整个站像一张正在构成的海报

从构成主义的斜向几何、对比色面和不对称平衡中提取规则，而不是复制某一张作品。

- Loader 中各色板使用不同角度和位移，但汇合时回到同一个平面。
- 分体导航沿用薄边、硬轮廓和有控制的偏转；每一块都有明确功能。
- 章节转场使用已有色面与标题的相对位移，不再添加无关粒子或光晕。
- 封面保留纸色、信号红、钴蓝和酸绿的交叠，让仓库与演示站属于同一个系统。
- 圆轨道、斜梁、切面和方块构成同一个原创几何标记；章节可以拆开再重组它，而不发明八套互不相干的标志。

参考：[Tate: Constructivism](https://www.tate.org.uk/art/art-terms/c/constructivism)。
这里借鉴历史视觉语汇，不把历史作品当作主题的可分发素材。

### 2. 编辑网格：用严谨的阅读层抵住大胆的展示层

主页可以有强烈张力，正文应有稳定节奏。巨幅字与克制的小字同时出现，
比所有区域都变大、都加描边、都做动画更有力量。

- 主要正文建议控制在约 `55–70ch`，根据语言与实际内容调整，而非作为强制常量。
- 章节标题、正文、图像说明和横向规则共享明确的起始线与边距。
- 在浅色、深色和六种 palette 下分别检查注释文字、边线和焦点状态。
- 让留白成为信息之间的停顿，不用无意义的指标、徽章或描述填满它。
- 手机先保证名字、简介、主要行动和导航能读能用，再决定装饰应该保留多少。

### 3. 个人出版物：从作品档案走到接触印样和打印成品

编号、细线、套准标记、接触印样和海报工作台可以形成一个连续的“个人出版物”故事。
已有画廊和打印功能不是附加彩蛋，而是这个方向的实际支撑。

- 项目案例使用清晰的标题、年份、角色和章节位置，让访客知道自己正在读哪一份档案。
- 画廊拖动、放大和视图切换继续作用于真实图片，避免不可操作的装饰性模拟器。
- 海报输出复用真实 CV 数据，输出结果能被保存，而不只是显示成功提示。
- 图版中的小标题强调真实能力，例如命令索引、原生锚点和打印导出，不写未测量的性能分数。

动效节奏可研究 [Dennis Snellenberg 的展示](https://www.awwwards.com/sites/dennis-snellenberg)，
学习的是留白、速度和交互层次，不使用其页面素材，也不暗示主题获得任何奖项。

### 导航补充：Agrumea 的留白与时间编排

参考页为实际观察过的 [Agrumea](https://www.agrumeafarm.it/en)。
它的价值不在“橙色加大字”这个表面组合，而在大面积单色幕布、克制的页眉、
有意错开的超大菜单项，以及各字符略有时差的双层文字滚动反馈。
本轮将这些关系转译为 Constructa 自己的纸色、palette 和几何标记，
不复用参考站的商标、内容、图像或源码。

菜单开关与章节滚动是不同的任务：菜单可以有一次完整的幕布转场，
章节仍保持真实文档和原生锚点。字符 hover 不是进入页面的唯一方法；
键盘 focus、Escape、减少动效偏好和关闭后的焦点恢复需要同样清晰。

## 微交互约定

| 操作 | 应解释的关系 | 需要避免 |
| --- | --- | --- |
| Loader 入场 | 分散色板逐渐成为统一色面，最后让位于内容 | 虚构百分比、无限等待、阻断深链接 |
| 导航 hover / focus | 当前意图和当前章节之间的区别 | 大幅跳动导致误点，只有鼠标才有反馈 |
| 导航点击 | 真实锚点、当前章节和页面位置同步 | 另加一个互相矛盾的 active-section observer |
| 字体重排 | 字形变化，但名字、字宽和语义保持稳定 | 文字不可读、标题整体抖动、每次滚动重新随机 |
| 像素地球 | 可暂停的装饰性运动 | 暗示正在跟踪访客位置，持续占用注意力 |
| 配色切换 | 同一内容获得另一种气氛 | 每个模块使用不同的转场风格，忘记减少动效偏好 |
| 对话框和命令索引 | 新任务开启，原页面仍在原位 | 背景继续响应操作，关闭后失去焦点 |
| 画廊与打印 | 浏览、编排和导出的是同一份真实内容 | 只出现动画或成功消息，却没有真实结果 |

### 章节开场不是同一种 reveal 重复八次

每个章节复用同一个标记几何，用不同的空间关系解释章节的角色。
动画由共享滚动进度与局部时间线驱动，不建立另一个全站屏幕切换器。

| 章节 | 色面与标记的转译 | 阅读层要保持 |
| --- | --- | --- |
| About | `unfold`，像展开一页自述 | 逐词着墨的句子、事实和引用仍在文档流中 |
| Experience | `track`，沿履历轨迹推进 | 年份、角色和完整经历有稳定阅读列 |
| Projects | `frame`，构成作品画框 | 主媒体、标题和案例操作是视觉中心 |
| Education | `orbit`，从轨道收拢到记录 | 学校、年份和证书信息按秩序对齐 |
| Skills | `matrix`，建立材料目录 | 分类与具体技能行可筛选、可打印 |
| Gallery | `scatter`，像接触印样铺开 | 图像仍能浏览、放大和原生滚动 |
| Contact | `gather`，色面与身份聚合成结尾 | 邮箱、社交链接和导出操作直接可用 |

这些形态属于同一套构成规则。低高度、小屏和减少动效情况下，
应收敛为不阻断内容的静态表现，而不是让访客多经过一组漫长的过场。

React Bits 可作为理解分层文字、导航响应和时间编排的参考：
[React Bits](https://www.reactbits.dev/get-started/index)。
主题仍使用 Astro、现有浏览器模块与 GSAP 独立实现；不引入 React island，
也不把 React Bits 的源码或素材重新打包进可分发主题。

封面为独立创作的矢量排版，使用项目已采用的本地字体，以及从
`src/components/ConstructionMark.astro` 读取的原创标记几何，避免宣传与 UI 身份漂移。
不存在被接受的 AI 设计概念图。
这轮概念生成服务返回额度 / 访问错误，所以不能声称“已忠实还原 AI 概念”。
宣传预览由真实浏览器截图构成，不替换实际 UI 文案，也不编造项目或功能。

截图脚本为 `scripts/capture-showcase.mjs`。使用已有 Chromium 与 Sharp，
网页截图在 `1440 × 900` 视口以 `2×` 像素密度生成，随后排成高分辨率图版。
它等待 Loader、滚动控制器、字体和首页入场就绪，通过真实按钮暂停地球，
并拒绝把空白页或 Astro 错误覆盖层收进宣传图。

```bash
# Start the existing project server first, then use its exact URL.
SHOWCASE_URL=http://127.0.0.1:4325/astro-constructivist/ node scripts/capture-showcase.mjs

# Cover artwork does not require a running server.
node scripts/capture-showcase.mjs --cover-only
```

PowerShell 可以先设置 `$env:SHOWCASE_URL`，再运行同一个 Node 命令。
PNG 是高分辨率原稿，WebP 用于 README，避免无谓地加载更大的文件。
这些是宣传素材，不会自动改变用户站点的 SEO 图片；站点元数据仍由 `cv.json` 控制。

发布、部署和提交主题目录需要另行确认。准备完素材，不等于已经完成公开发布。
