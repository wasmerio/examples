# Wisp 图表布局规则

字号、线宽的硬规则见 SKILL.md；这里讲**怎么摆**和**怎么用颜色**。目标：一眼读懂、安静、和正文排版一致——图是手册里的一张插图，不是一张海报。

## 1. 网格与尺寸

- 所有节点的 `x / y / w / h` 取 8 的倍数（lint 会对不在 8px 网格上的元素给出 `grid` 警告）。
- 常用节点尺寸（宽 × 高）：短标签 96×48；常规 128×56 / 144×56；两行标签 160×64；强调节点可以更大，不要超过 192×96。
- 节点横向间距 ≥ 64，纵向间距 ≥ 32；**要在连线上放标签时，间距 ≥ 96**。
- **按正文栏宽度画**：Wisp 的正文栏约 710px，图的自然宽度控制在 **640–700px**（文字就是原尺寸 14px）；更宽的图会被等比缩小，超过约 1000px 字就看不清了。流程从上到下走，分支排成并列的列；横向一字排开的长流程改成纵向，或拆成两张。
- 画布整体从 (0, 0) 附近开始即可，导出时会自动裁边；不需要画背景矩形。

## 2. 留白与对齐

- 同一行/同一列的节点中心对齐（y 或 x 相同），不要靠肉眼错开几像素。
- 组与组之间的留白大于组内节点的间距（至少 1.5 倍），靠留白而不是靠边框分组。
- 标题与内容之间至少留 32px；注释与内容之间至少留 32px。
- 一张图的主流向只有一个：从左到右，或从上到下（Transformer 这类堆叠结构自下而上也可以，但要全图一致）。

## 3. 箭头路由

- Excalidraw 骨架：两个矩形正对（一条轴上投影重叠）时箭头是水平 / 竖直的直线，否则是中心连线上的斜线；要拐弯用 `via` 给拐点。它不会自动绕路：摆放节点时让连线不穿过第三个节点，做不到就调整布局，或改用 draw.io。
- **优先横平竖直**：把节点摆在行、列上。斜线只用于扇出 / 汇聚（一个节点到一排节点），而且同一张图里斜率尽量一致。
- 不要出现交叉的连线；必须交叉时让它们垂直相交，不要斜交。
- 一个节点同时有多条出线/入线时，把目标节点沿纵向均匀排开（扇出），例如 X → Q/K/V。
- 反馈、残差、循环用**虚线**，颜色用 muted（灰）或语义色（残差、梯度用玫红）。
- 箭头标签 ≤ 6 个汉字或 12 个字符；放在较长的线段上。太短的线段不要加标签（标签会压住箭头头部）。
- draw.io 中用 `edgeStyle=orthogonalEdgeStyle` 的直角折线，拐点落在 8px 网格上。

## 4. 分组框

- 分组框用浅灰填充（surface）+ 浅灰虚线边（border），标签放在左上角，字号 12，颜色 muted。
- 分组框内边距 ≥ 24；不要嵌套超过两层。
- 分组框不要使用 hue 色（避免和语义色混淆），也不要加阴影。
- Excalidraw 骨架里用 `color: "muted"`、`dashed: true` 的大矩形表示分组框；注意它的 label 会居中，需要左上角标签时用单独的 `texts` 条目。

## 5. 标题与注释

- **放进文章的图不写标题**：题注（`<figcaption>`）已经是标题，图里再写一遍只是重复，还占掉一行高度。单独使用的图（README、幻灯片）才写标题：18px，放在左上角，与内容左边缘对齐，一张图一个。
- 无障碍文本：站点引用时 alt 写入 SVG 的 `<title>`；没有 alt 时取 `size: "title"` 的文本 / draw.io 页面名，其余文字拼成 `<desc>`。所以 draw.io 的页面名要起得有意义。
- 注释：12px，muted 色，放在图的最下方、与内容左边缘对齐，一两句话讲完。连线上放不下的说明（“只传下标”“复用上一步的结果”）也写到这里，不要硬塞成连线标签。

## 6. 信息密度

- 一张图只讲一件事。节点数建议 ≤ 12，超过就拆成两张图，或者把细节折叠成一个节点。
- 每个节点一个概念，标签是名词或短语，不写句子。
- 强调只用一处（hue 节点线宽 2；中性节点换成墨色描边），通常是最终输出或要讲解的关键节点。强调不靠换颜色。

## 7. 颜色

调色板是一组**印刷油墨**：低彩度的深色描边 + 接近纸色的淡洗填充，和页面的墨色正文、唯一的 teal 强调色放在一起不跳。用法比色值更要紧：

- **默认节点是中性的**：`surface` 底、`muted`（或 `fg`）1px 描边、`fg` 文字。输入、LayerNorm、Add、普通处理步骤都是中性节点。
- **颜色只给语义角色**：Q/K/V、权重、激活、梯度、偏置、掩码，以及 `highlight` / `active` / `done` / `error` 这类状态。同一篇文章里同一语义始终同一个 hue。
- **一张图最多 3 种 hue**（`slate` 是中性灰，不计）。一张图要讲的通常只是其中两三个角色，其余的回到中性。lint 超过时给 `hue-count` 警告。
- **不要用颜色区分兄弟节点**：并排的 4 个专家、3 个分支、5 个步骤，用同一种样式 + 文字区分；它们同属一个语义时用同一个 hue。
- **强调 = 加粗描边或 `highlight`**，不是再引入一个颜色。
- **节点里的字用 `fg`**。彩色文字只用于独立的、和某个角色绑定的标签（连线上的「梯度」、图例说明），并且用该 hue 的 stroke 色。
- 连线默认 `fg`；虚线（可选、反馈）用 `muted`；只有表达某个角色的数据流（残差、梯度）才用 hue。

## 8. 中文标签

- 字号 14 时，**每行不超过 8–10 个汉字**；超过就换行（骨架里用 `\n`，draw.io 里用 `&lt;br&gt;`）。
- 节点宽度 ≈ 汉字数 × 14 + 32：6 个字约 120→128，8 个字约 144→160。
- 中英混排时中英文之间留一个空格（`多头注意力 MHA`）；公式和符号（Q·Kᵀ/√d）保持原样，不拆行。
- 手绘风格（Excalidraw）中文回落到 Noto Sans SC，不使用小赖体；不要靠加粗/斜体强调中文。
- 节点内文字用 `fg`（骨架默认如此）；独立标签需要彩色时用 hue 的 stroke 色——每个 stroke 在 light/dark 下对页面底色和自己的 fill 都 ≥ 4.5:1。

## 9. 手绘（hand）与规整（clean）怎么选

|            | hand（Excalidraw）                     | clean（draw.io）           |
| ---------- | -------------------------------------- | -------------------------- |
| 适合       | 概念、直觉、流程示意                   | 精确结构、层次、对齐要求高 |
| 节点数     | ≤ 12                                   | 可更多                     |
| 连线       | 直线                                   | 直角折线、曲线             |
| 同一篇文章 | 风格尽量统一，不要两种混用在同一张图里 |                            |
